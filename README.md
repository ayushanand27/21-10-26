## 1. The problem in plain words

A power plant records five sensors (`X1 … X5`) once per minute. A small number of minutes are marked as **anomalies**
(`target = 1`) — only **0.86 %** of all minutes (14,038 out of 1.64 million). We must predict which of the 409,856 test minutes
are anomalies.

The competition scores the **F1 score of the anomaly class**. F1 balances two things:
* **precision** — when we say "anomaly", how often are we right?
* **recall** — of all real anomalies, how many did we catch?

Because anomalies are so rare, plain accuracy is useless: a model that always says "normal" is 99.14 % accurate but catches
nothing. F1 forces the model to actually find anomalies without raising too many false alarms.

## 3. Detective work: what the data was hiding

Before any modelling we studied the raw numbers. Five discoveries changed everything:

1. **The sensors were disguised with exp/log.** Taking `log(X1)`, `exp(X2)`, `log(X3)`, `log(X4)`, `exp(X5)` gives clean,
   physical values: a voltage around **240 V** (X2), two **integer counters** 0–88 (X3, X4), a **level 1–32** (X5) and a small
   analogue reading (X1). The "crazy outliers" like 10³⁸ are just `exp(88)` — so we **decode instead of deleting** them.
2. **The dates were broken.** For days 1–12 the day and month were swapped (2021-01-02 was stored as 2021-02-01). The rows
   themselves are in the correct time order, so we repaired the calendar by walking through the file.
3. **One reading per minute.** Train + test together have ~1,440 rows per day = 24 × 60 minutes.
4. **The test set is a random 20 % of the *same* minutes.** Every day is split about 80 / 20 between train and test, and both
   files keep their rows in time order. So the test minutes sit *between* training minutes whose answers we know.
5. **Anomalies come in short bursts.** If one minute is an anomaly, the next minute is too 74 % of the time
   (mean burst length 3.8 minutes). Typical signature: voltage dips (≈236 V instead of ≈242 V), counters switch on, level 17–19.

> **Key insight:** this is not "classify each row on its own". It is "put the minutes back in order, then look at what is
> happening around each minute".

## 4. The big idea: rebuild the clock

Think of each day as two decks of cards (train minutes and test minutes), each in order, that were separated. We want to
shuffle them back together correctly. Sensors change **smoothly** from minute to minute, so the right interleaving is the one
with the **smallest jumps** between neighbouring readings.

* **Hard alignment (dynamic programming).** For every day we compute the *exact* best interleaving with a dynamic-programming
  algorithm (`src/pipeline.py: _merge_two`). Tested on training data where we know the truth: a hidden minute lands within
  **1 minute** of its true position (median error 1, versus 17 for a naive guess).
* **Soft alignment (forward–backward).** Near the edge of a burst, being one minute off flips the answer. So we also compute
  the **probability** of every possible position (`src/softalign.py`) and give the model *expected* neighbour labels, e.g.
  "70 % chance the minute before me was an anomaly".
* **Alignment bagging.** We rebuild the timeline with **three** reasonable cost settings and average the model's predictions
  across them, so mistakes caused by one particular alignment cancel out.

## 5. What the model looks at (features)

About **240 features** per minute, in three groups:

| Group | Examples | Why it helps |
|---|---|---|
| **Sensor context** (~190) | value now vs. the average of the last 5 / 15 / 60 / 240 minutes, ups/downs, voltage drop, how long the counters have been on, time of day, month, year | anomalies are *changes*, not absolute values |
| **Neighbour labels** (27) | share of anomalies among the nearest labelled minutes before/after, distance to the nearest labelled anomaly, the day's anomaly rate | bursts: a neighbour being an anomaly is a strong clue |
| **Soft-alignment** (23) | expected neighbour labels, chance of being inside / at the edge of a burst, alignment uncertainty | handles the ±1-minute ambiguity |

**No cheating:** a minute's **own** label is never used to build its own features.

## 6. Testing honestly (validation)

A score is only useful if it predicts the leaderboard. So we copied the real test situation inside the training data:

1. **Hide 20 % of the training minutes** (the *hold-out*, 327,852 rows, 2,680 anomalies) and treat them exactly like test
   minutes: positions re-estimated by the alignment, labels invisible.
2. **Training rows get "test-like" features too:** the training data is cut into 10 chunks; each chunk is hidden in turn and
   re-placed by the alignment, so the model learns from features that look like what it will see at test time.
3. **Decisions are made on the hold-out only, never on the public leaderboard.** Thresholds are checked with *cross-fitting*
   (choose on one half of the hold-out, score on the other) and *bootstrap* resampling of whole weeks.

It worked: the hold-out predicted the public score every time (public ≈ hold-out + 0.006, because test minutes have more
labelled neighbours: 80 % vs 64 %).

## 7. Models we trained and how they did

All scores are on the honest hold-out, from the executed notebook (anomaly-class F1 at the best threshold):

| Type | Model | F1 (anomaly) | PR-AUC |
|---|---|---|---|
| Classical | Logistic Regression (tuned C) | 0.843 | 0.913 |
| Classical | Linear SVM | 0.850 | 0.915 |
| Classical | RBF-kernel SVM (sub-sampled) | 0.741 | 0.609 |
| Classical | K-Nearest Neighbours | 0.761 | 0.793 |
| Classical | Decision Tree (tuned depth / leaf) | 0.847 | 0.917 |
| Advanced | Random Forest | 0.860 | 0.934 |
| Advanced | **XGBoost** | **0.884** | 0.951 |
| Advanced | CatBoost | 0.877 | 0.946 |
| Advanced | **LightGBM** (random-search tuned) | **0.884** | **0.953** |
| Deep learning | MLP (PyTorch) | 0.856 | 0.921 |
| Deep learning | Dilated 1-D CNN over ±32-minute windows (PyTorch) | 0.857 | 0.922 |
| Ensemble | Weighted blend (weights fitted on the hold-out) | 0.884 | 0.952 |

**Why these results make sense:** linear models only add effects up; kernel SVM and KNN struggle with 240 heavy-tailed
features and must be sub-sampled; single trees are unstable. Gradient-boosted trees (LightGBM, XGBoost, CatBoost) handle
mixed scales, redundant features and interactions best. The neural networks learn burst shapes but don't beat the boosted
trees on this tabular data. Hyper-parameters were tuned with `GridSearchCV` + `GroupKFold` by week (classical) and a
random search with early stopping (LightGBM).

**What each feature group is worth (LightGBM ablation):** raw sensors only 0.642 → sensor context only 0.867 →
neighbour labels only 0.844 → **everything together 0.884**.

## 9. Every experiment: kept and rejected

Each idea was tested on the hold-out with the same paired protocol (`src/eval_utils.py`). Scripts in [`experiments/`](experiments).

| Idea | Effect on the hold-out | Decision |
|---|---|---|
| Test-like (out-of-fold re-placed) training features | F1 0.877 → 0.884 | ✅ kept |
| Soft (posterior) alignment features | F1 0.8836 → 0.8866, PR-AUC 0.9491 → 0.9508 | ✅ kept |
| Seed bagging (LightGBM × 3) | lower variance | ✅ kept |
| Soft pseudo-labels of unlabelled minutes (at prediction time) | +0.0023 F1, better in 93 % of bootstrap resamples | ✅ kept (v3) |
| **Alignment bagging** (3 alignments) | cross-fitted F1 +0.0033, better in 90 % of resamples | ✅ kept (v6) |
| Alignment bagging + pseudo-labels | best F1 0.8886, better in 99.5 % of resamples | ✅ kept (v7) |
| Stage-2 stacking on neighbouring predictions | −2 points | ❌ |
| Smoothing scores over neighbouring minutes | no gain | ❌ |
| 20 instead of 10 out-of-fold chunks | −0.5 point | ❌ |
| Different alignment cost weights (single alignment) | no gain | ❌ |
| Learned alignment cost (−log P(Δ) per sensor) | worse placement at burst edges | ❌ |
| Separate thresholds for burst edges / isolated minutes | no gain | ❌ |
| Separate thresholds per year | worse (0.8845 vs 0.8855) | ❌ |
| Anomaly rate of identical sensor vectors | −0.6 point | ❌ |
| Pseudo-labels inside the *training* features too | −0.0035 vs v3 | ❌ |
| XGBoost / CatBoost added to LightGBM | ≈ no gain (blend ≈ 87 % LightGBM) | kept only for variety |

**Where the remaining errors are:** about 60 % at the first/last minute of a burst (±1-minute ambiguity, partly label noise)
and about 20 % are isolated one-minute anomalies whose sensors look normal. These limit everyone — the top teams are all
within ~0.001 of each other.

## 11. Robustness checks

* **Public/private split simulation** (`scripts/private_split_sim.py`): splitting the hold-out into random halves 400 times
  shows the same model can score up to ±0.015 differently on two halves purely by chance; no random half fell below 0.871.
* **Backtest over time:** training on earlier years and testing on later years (notebook section 9.1) — ranking quality holds,
  the best threshold shifts as the anomaly rate falls (2.4 % in 2020 → 0.46 % in 2024).
* **Residual analysis and calibration** (notebook section 9.2): residuals by month and hour show no systematic bias; errors
  concentrate at burst edges and isolated minutes.
* **Interpretation** (notebook section 9.3): SHAP contributions — sensor context ≈ 77 %, neighbour labels ≈ 21 %, raw
  sensors ≈ 2 % of the total importance.
* **Predicted anomaly rate per year** on the test set matches the training rate per year (e.g. 2021: 1.18 % vs 1.26 %,
  2024: 0.45 % vs 0.46 %).

## 12. Frequently asked questions

**Why does the notebook's own `submission.csv` score 0.8915 when the best file scores 0.8930?**
The notebook (section 11) runs the same final method (LightGBM × 3 + alignment bagging + pseudo-labels) and picks its
threshold from its own hold-out run (0.577). The submitted v6 uses threshold 0.465 from the scripts' hold-out run. Same
method, different decision point; the exact v6 file is regenerated by `scripts/v6_v7_alignbag.py`.

**Is using the neighbouring training labels allowed?**
Yes. The training labels are given to everyone; we only use labels of *other* minutes, never the predicted minute's own label,
and we validated the whole procedure on a hold-out that mimics the test set exactly.

**Why not tune on the public leaderboard?**
The public board is only half of the test set (≈ 1,750 anomalies); tuning to it fits noise and usually drops on the private
board. Every choice here was made on the hold-out.

## 13. How to run everything

**The notebook on Kaggle (recommended)**
1. *File → Import Notebook* → `anomaly_detection.ipynb`; *Add Input* → the competition data.
2. *Settings → Accelerator → GPU T4*, Internet off.
3. *Save Version → Save & Run All* (≈ 3.5 h, runs in the background). Outputs land in `/kaggle/working/`.

**The notebook locally**
```bash
pip install -r requirements.txt
jupyter nbconvert --to notebook --execute anomaly_detection.ipynb --ExecutePreprocessor.timeout=20000
```
Put the data in `data/`. Set `SMOKE=1` for a 5-minute end-to-end test on every 25th day; `FAST_MODE = True` (setup cell)
shortens the full run.

**Reproduce every submitted file**
```bash
pip install -r requirements.txt
bash scripts/reproduce.sh     # CPU only, ~4 h on 4 cores / 16 GB; intermediate tables go to ./work (override with WORK=...)
```

## 15. Glossary

* **Anomaly / class 1** — a minute the plant marked as abnormal.
* **F1 score** — harmonic mean of precision and recall for the anomaly class; 1.0 is perfect.
* **PR-AUC** — area under the precision–recall curve; measures ranking quality regardless of threshold.
* **Threshold** — the probability above which we call a minute an anomaly.
* **Hold-out** — part of the training data we hide and use as a fake test set.
* **Out-of-fold** — features or predictions for a row computed without using that row's own label.
* **Dynamic programming (DP) alignment** — an exact algorithm that finds the best way to interleave two ordered lists.
* **Soft alignment** — instead of one best interleaving, the probability of every possible position.
* **Pseudo-labels** — using the model's own predicted probabilities for unlabelled minutes as temporary labels.
* **Seed bagging / alignment bagging** — averaging several models (different random seeds / different alignments) to reduce
  random errors.
